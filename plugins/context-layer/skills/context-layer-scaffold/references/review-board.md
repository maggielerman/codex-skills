# Review Board Operating Pattern

The Review Board Operating Pattern is optional during scaffold setup, but recurring review-board work should use a dedicated trigger skill after installation.

## When To Recommend It

Recommend including this scaffold when the repo has:

- screenshot, route, UI, or design QA workflows
- evidence packets, audit reports, or visual comparison work
- image, asset, content, metadata, taxonomy, or catalog cleanup
- product review, PDP, feed, collection-management, or merchandising workflows
- requests for numbered boards, human corrections, or compare/contrast review

## Files To Install

Copy from `assets/templates/review-board-operating-pattern/`:

- `DOCS/development/review-board-operating-pattern.md`
- `DOCS/evidence/templates/review-board-operating-pattern/README.md`
- `DOCS/evidence/templates/review-board-operating-pattern/review-session-template.md`
- `DOCS/evidence/templates/review-board-operating-pattern/corrections-template.md`

Then update:

- `DOCS/README.md`
- `DOCS/index.md`
- `DOCS/development/index.md`
- `DOCS/PROJECTS/README.md`
- `AGENTS.md`

## Core Loop

1. Open a numbered project doc for the review stream.
2. Define target and source rules.
3. Generate numbered JPG review boards.
4. Optionally generate a PDF bundle.
5. Collect numbered human feedback.
6. Convert feedback into a bounded apply pass.
7. Verify touched records, screens, docs, or artifacts.
8. Record checkpoints and evidence paths.
9. Delete temporary packets unless explicitly preserved.
