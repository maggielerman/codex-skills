# Refinement Checklist

Use this file to keep refinement passes focused and decision-light.

## 1. Tokens

Check first:
- Are background, foreground, muted, line, and accent values clearly defined?
- Do major surfaces draw from the same token family?
- Are typography choices deliberate and consistent with the starter mode?

## 2. Hierarchy

Check next:
- Does each section or panel have one job?
- Is the first viewport obviously the most important area?
- On app shells, is there one primary workspace and one secondary layer?

## 3. Surface system

Check:
- Are shadcn components used as foundations rather than ad hoc styled boxes?
- Do panels, cards, or shells share curvature, border treatment, and contrast rules?
- Is there an obvious “canonical surface” pattern developers can reuse?

## 4. Density and copy

Check:
- Could 20-30% of the copy be removed without losing clarity?
- Are labels and headings operational on app shells instead of marketing-speak?
- On marketing starters, is the brand/promise stronger than the generic section chrome?

## 5. Motion and affordance

Check last:
- Is there at least one meaningful motion or reveal when it improves the result?
- Are interactions clear even without decorative animation?
- Do hover and focus states reinforce the design system rather than fight it?

## Done criteria

The refinement pass is successful when:
- the interface no longer reads like a raw starter
- the system feels more coherent, not just more decorated
- follow-on contributors can still see the underlying patterns clearly
