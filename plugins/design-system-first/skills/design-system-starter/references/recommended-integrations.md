# Recommended Integrations

Use this file when the user wants suggestions for follow-on setup, MCPs, or private registry enablement.

## Recommended follow-on skills

- `$shadcn`
  - Use for component discovery, registry additions, and shadcn-specific repairs.
- `$frontend-skill`
  - Use for stronger art direction, especially on `marketing-only` starters.
- `$react-best-practices`
  - Use after larger React/Next edits or performance-minded refactors.
- `$docs-system-scaffold`
  - Use when the user wants a full docs system beyond the starter's baseline docs add-on.
- `$design-system-refine`
  - Use after content or product requirements become clearer and the starter needs a second pass.

## Suggested MCPs / plugins

Recommend these when helpful, but do not block the scaffold on them:

- Vercel
  - Best for previews, deploys, and runtime logs.
- GitHub
  - Best for repo publishing, PRs, and CI follow-up.
- Playwright / browser automation
  - Best when the user wants end-to-end UI verification.

## Secrets And Registry Guidance

Do not invent private registry or vendor token names.

When the user mentions paid blocks, private registries, or external design resources:
- confirm which provider they mean
- ask whether they want placeholders written locally or only verbal guidance
- if writing placeholders, keep them clearly optional and commented
- never fail the scaffold because a private token is missing
